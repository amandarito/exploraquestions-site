# ExploraQuestions — website

A one-page marketing + support site. Plain HTML, CSS and JavaScript. No build step, no framework, no npm install.

## Files

```
index.html          the whole page — all copy lives here
styles.css          all styling, sectioned and commented in page order
main.js             hero question rotation, scroll reveals, the sample-question pool
build-preview.py    bundles everything into a single preview.html (optional)
preview.html        generated — one self-contained file, handy for sharing a link-free preview
assets/fonts.css    self-hosted Fraunces + Karla (no third-party font requests)
assets/favicon.svg  rainbow app mark
assets/og-image.png social preview card (1200×630)
.nojekyll           tells GitHub Pages to serve the files as-is
```

## Publishing on GitHub Pages

1. Create a repo and push these files to the root of the `main` branch.
2. Repo → **Settings → Pages** → Source: *Deploy from a branch* → `main` / `/ (root)`.
3. The site appears at `https://<user>.github.io/<repo>/` in a minute or two.
4. For a custom domain, add it under Settings → Pages and put the domain in a file called `CNAME` at the repo root.

To preview locally, open `index.html` in a browser, or run `python3 -m http.server` in this folder.

`preview.html` is a single self-contained copy of the whole site — fonts and all — generated by `python3 build-preview.py`. It's useful for emailing a preview or dropping into a viewer that only takes one file. **Don't deploy it:** the multi-file version is the source of truth, and `preview.html` goes stale the moment you edit anything. Re-run the script after changes.

## Before you submit to the App Store

- [ ] Replace the two `href="#"` placeholders on the store buttons (there are two pairs: hero and the closing section) with the real App Store and Google Play listing URLs.
- [ ] Set the real Premium price in the `.plan-price` line and delete the purple `.plan-note` reminder underneath it.
- [ ] Point `support@exploraquestions.app` and `privacy@exploraquestions.app` at inboxes someone actually reads — Apple checks that the support address works.
- [ ] Have the **Privacy policy** section reviewed. Right now it describes an on-device app with optional crash reporting; it must match what the app really does and what you declare in App Store Connect's privacy questionnaire.
- [ ] Replace the **Terms of use** placeholder, or link Apple's standard EULA instead.
- [ ] Update `og:url` and the `og:image` path in `<head>` to your real domain.
- [ ] Check every anchor link resolves — Apple rejects support URLs with 404s.

Apple's support URL wants a reachable contact route and self-service answers on a page that loads over HTTPS without a login. That's what the **Support** and **FAQ** sections are for; you can point the App Store Connect *Support URL* field at `https://yourdomain.com/#support` and *Marketing URL* at the root.

## Editing copy

**`exploraQuestions-website-copy.docx`** (delivered separately) covers the page down to the privacy band — menu, top of page, how it works, why it works, themes, privacy — as a three-column table — reference code, current copy, blank column for the rewrite — with screenshots above each table (all three steps for "How it works"). Upload it to Google Docs and hand it to whoever is writing. The codes (`TOP-2`, `WHY-5`…) run in the same order the copy appears in `index.html`. Pricing onward isn't in it.

Everything a copy editor needs is also in `index.html` as plain text. Sections appear in this order and are marked with comment banners:

`nav → hero → how it works → why it works → themes → privacy promise → pricing → support + FAQ → privacy policy → closing CTA → footer`

The sample questions used by the rotating hero card live in the `QUESTIONS` object at the top of `main.js`, grouped by theme. Add or change as many as you like — the year cycles through each theme's list in order. The four sample cards under "Why it works" are plain HTML in `index.html`.

## Phone screenshots

The three phone screens under **How it works** are placeholders — they're HTML and CSS recreations of the app, not real screenshots. To swap in the real thing, replace the whole `<div class="phone grain">…</div>` block with an image:

```html
<img class="phone-shot" src="assets/shots/today.png" alt="The Today screen, showing the day's question">
```

and add this to `styles.css` (the mockup rules can then be deleted):

```css
.phone-shot {
  width: 300px; max-width: 100%;
  aspect-ratio: 9 / 19.5; object-fit: cover;
  border: 10px solid #1B1E2E;      /* the handset frame */
  border-radius: 46px;
  box-shadow: 0 0 0 2px #3A4059, var(--shadow-lg);
}
```

If your screenshots already include a device frame, drop the `border` and `box-shadow` lines and keep just the width and aspect ratio.

The mockups already use `aspect-ratio: 9 / 19.5` — a real handset — so a standard iPhone screenshot drops in at the same size without shifting the layout. Export at 2× or 3× (roughly 750–1200px wide) so they stay sharp, and keep the alt text describing what's on the screen.

## Artwork

The six theme illustrations are **stand-in SVGs** drawn to match the app's icon set. They're defined once at the top of `index.html` in a `<svg>` sprite and used with `<use href="#art-cat">`.

To swap in the real artwork, export each icon as a transparent PNG (256×256 is plenty) into `assets/art/`, then replace each usage — for example:

```html
<!-- from -->
<svg class="art art-lg"><use href="#art-cat"></use></svg>
<!-- to -->
<img class="art art-lg" src="assets/art/cat.png" alt="">
```

The `.art` classes control size, so nothing else needs to change. The mapping is: Courage → cat, Gratitude → rainbow, Possibility → hot-air balloon, Well-Being → apple, Connection → heart, Clarity → butterfly, plus a sprig and a sunflower used in the question chip, the "Why it works" cards and the closing section.

## Colour

`styles.css` opens with the palette. The six theme colours come straight from the app; `--card-blue` is the question card, `--slate` the privacy band, `.hero-name` the app name above the tagline, `--brand` (deep teal) is for the small section labels and links, and `--cta` is every primary button — set to the same blue as the question card, deliberately away from red so buttons never read as error states. Red now appears only where it belongs: the Connection theme, which is coral in the app. Sections alternate white → pale mint → white → dark slate → pale blue → white → pale mint → deep teal → ink, with the rainbow rule bookending the top and bottom.

Any block can be recoloured by setting `data-cat="green|orange|purple|sky|coral|indigo|teal|pink"` on it — that sets `--c`, `--c-pale` and `--c-deep` for everything inside.

## Accessibility and performance notes

- Fonts are self-hosted and preloaded, so there are no external requests at all — the page works offline once cached.
- `prefers-reduced-motion` turns off the reveal animations, the question rotation and smooth scrolling.
- Colour contrast clears WCAG AA. Each theme colour has a `--*-deep` variant used wherever it has to carry white text or sit on its own pale tint; the bright originals are kept for the phone mockups so they match the real app.
- There's a skip link, visible focus rings, and the layout reflows to a single column below 980px.
